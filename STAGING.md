# Тестовый стенд: проверка изменений до прода

Стенд — копия бота на вашем компьютере (Docker) со своим **тестовым ботом** и **тестовой группой**. Клиенты и боевые данные не затрагиваются: у стенда своя база, свой Redis и свой файл настроек `.env.staging`.

Сообщения тестового бота получаются через **long polling** (`php artisan telegram:poll`): нужен только исходящий доступ к `api.telegram.org`, ни ngrok, ни cloudflared не нужны.

## Один раз: создать тестового бота и группу

1. В @BotFather: `/newbot`, имя любое, username на `bot`. Сохраните токен.
2. Создайте группу, включите «Темы», добавьте бота **администратором** (управление темами, удаление и закрепление сообщений).
3. Узнайте id группы (`-100…`) — например, через @getidsbot.
4. `cp .env.staging.example .env.staging` и заполните: `TELEGRAM_TOKEN`, `TELEGRAM_GROUP_ID`, `BACKUP_TELEGRAM_CHAT_ID` (ваш id), при желании `TELEGRAM_BROADCAST_TOPIC_ID` (id темы рассылки в тестовой группе), `APP_KEY` (любая строка `base64:` + 32 случайных байта), `TELEGRAM_SECRET_KEY` (любая случайная строка).

`.env.staging` в git не попадает. **Токен боевого бота сюда не вставлять.**

## Запуск

```bash
docker compose -p tgstaging -f docker-compose.staging.yml up -d --build
docker compose -p tgstaging -f docker-compose.staging.yml logs -f poll
```

Первый запуск долгий (сборка образа, установка зависимостей, миграции). Когда в логе `poll` появится «Получаю обновления…», откройте тестового бота с любого аккаунта и отправьте `/start`.

Если у тестового бота когда-то был установлен webhook, один раз снимите его:

```bash
docker compose -p tgstaging -f docker-compose.staging.yml run --rm poll php artisan telegram:poll --force --once --timeout=0
```

Остановка: `... down` (данные остаются), полный сброс данных: `... down -v`.

## Тесты

```bash
docker compose -p tgstaging -f docker-compose.staging.yml exec app php artisan test
```

Допустимы только известные старые падения (AI-провайдеры, `TgMessageServiceTest`, `WebhookServiceTest`, `BannedContactMessageTest`, `SendAi*JobTest`). Тесты идут на SQLite в памяти и боевую или стендовую БД не трогают.

## Сценарий проверки перед выкаткой

С отдельного аккаунта (клиент) и аккаунта администратора группы:

1. `/start` → ФИО из трёх слов (`123` и «Иванов Иван» отклоняются) → телефон (неверная длина отклоняется) → email.
2. Договор: загрузите PDF в группе (`/panel` → «Заменить договор»), клиент нажимает «Принимаю условия».
3. Меню без доступа: только описание кабинетов, правила, как добраться, договор.
4. В теме клиента «Открыть доступ»: меню расширяется, приходят два сообщения, значок темы ✅, карточка закреплена.
5. Кнопки ссылок и кодов; `/set_link график https://…` и «Ротация доступов» — у клиента открывается новая ссылка.
6. Клиент пишет (значок 💬), админ отвечает из темы (значок ✅), стикер/фото, массовая рассылка.
7. «Закрыть обращение»: клиенту ничего не приходит; новое сообщение клиента открывает тему.
8. `/backup_to я`, `/backup_days 1`, `/backup_now` (файл приходит в личку).
9. Если менялись миграции — восстановите копию боевой БД на стенд (`scripts/restore-db.sh`) и примените миграции.

## Выкатка на прод после проверки

```bash
# на сервере, в /var/www/tg-support-bot
# 1. в группе: /backup_now (дождаться файла)
git pull
chown -R www-data:www-data app resources tests routes
docker compose up -d --force-recreate app queue scheduler   # restart не перечитывает .env
docker compose exec -T app php artisan telegram:set-commands   # если менялись команды
scripts/smoke-test.sh
```

`scripts/smoke-test.sh` только читает: проверяет контейнеры, сайт, webhook, очередь Telegram и свежие ошибки в журнале; код выхода 1 — есть проблемы.

Откат: `git checkout <прежний коммит>` и пересоздание контейнеров; данные — `scripts/restore-db.sh` из последней копии.
Тесты на проде не запускаем — они грузят сервер и пишут «testing» в боевой журнал.

## Как стенд защищает прод

- `telegram:poll` отказывается запускаться при `APP_ENV=production`.
- Если у бота уже задан webhook (как у боевого), команда останавливается и ничего не снимает; без `--force` webhook не трогается.
- Стенд читает только `.env.staging`: боевой `.env` в контейнер не подключается.
